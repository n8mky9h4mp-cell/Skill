## 功能需求完整示例（按角色 + 详尽交互）

### 6.1 患者端功能

> **模块描述**：面向患者用户提供的所有操作功能，包括预约挂号、查看报告、在线支付等。

#### FR-1.1 预约挂号

- **优先级**：P0

- **需求描述**：患者应能够通过小程序查看科室列表、选择医生、预约挂号。

- **业务流程**：
  1. 患者进入首页，点击"预约挂号"
  2. 系统展示科室列表（按热度排序）
  3. 患者选择科室 → 系统展示该科室下所有医生的排班信息
  4. 患者选择日期和时段 → 点击"确认预约"
  5. 系统校验号源是否充足 → 扣减号源 → 生成预约记录
  6. 系统发送预约成功通知（短信/微信）

  **分支流程**：
  - 号源已满 → 提示"该时段已满，请选择其他时间"，预约按钮置灰
  - 患者未实名认证 → 引导先完成实名认证再预约

  **异常流程**：
  - 网络超时 → 提示"网络不稳定，请稍后重试"，不生成预约记录

- **交互说明**：
  - **页面入口**：首页底部 Tab 栏「挂号」图标，点击进入
  - **操作路径**：
    首页「挂号」→ 科室列表页 → 点击目标科室 → 医生排班页 → 选择日期 → 选择时段 → 点击「确认预约」→ 预约成功页
  - **页面布局与元素**：
    - **科室列表页**：顶部标题"选择科室"；搜索框（支持科室名称模糊搜索）；科室卡片列表（每个卡片包含科室图标、科室名称、科室简介、今日可挂号源数量）；底部无操作按钮
    - **医生排班页**：顶部显示当前科室名称；日期选择区（横向滚动，展示当前日期起 7 天，每天显示"月/日 周X"，选中状态高亮）；时段列表（按上午/下午/晚上分组，每个时段卡片显示时间范围，如"08:00-12:00"，剩余号源数量，号源 > 0 时可点击，号源 = 0 时置灰不可点）；底部「确认预约」按钮（固定底部，号源未选时置灰）
    - **预约成功页**：顶部对勾图标 + "预约成功"大标题；预约信息卡片（科室名称、医生姓名、预约日期、预约时段、就诊地址）；「查看我的预约」按钮（主色调）；「返回首页」按钮（次要色调）
  - **交互反馈**：
    - 点击科室卡片 → 跳转至医生排班页，加载时展示骨架屏
    - 选择日期 → 日期高亮，下方时段列表刷新为该日期的排班数据
    - 点击时段 → 卡片边框高亮，底部「确认预约」按钮变为可点击状态
    - 点击「确认预约」→ 展示加载态（按钮显示"提交中..."），成功后跳转预约成功页并触发微信服务通知；失败时 Toast 提示具体错误原因，按钮恢复可点击状态
    - 下拉刷新 → 科室列表重新加载，顶部展示刷新动效
  - **状态变化**：
    - 预约前：号源数量显示为"剩余 X 号"
    - 预约成功后：该时段号源数量减 1，页面跳转
  - **手势支持**：
    - 科室列表支持上下滑动浏览
    - 日期选择区支持左右滑动切换日期
    - 左滑返回上一页

- **字段详情**：

| 字段名称 | 字段标识 | 类型 | 必填 | 说明 |
|----------|----------|------|------|------|
| 预约单号 | appointment_id | String(32) | 是 | 雪花算法生成 |
| 患者 ID | patient_id | String(32) | 是 | 关联患者表 |
| 医生 ID | doctor_id | String(32) | 是 | 关联医生表 |
| 预约日期 | appointment_date | Date | 是 | 格式 YYYY-MM-DD |
| 预约时段 | time_slot | Enum | 是 | 上午/下午/晚上 |
| 状态 | status | Enum | 是 | 待就诊/已取消/已完成/已过期 |
| 创建时间 | created_at | DateTime | 是 | - |
| 取消时间 | cancelled_at | DateTime | 否 | 用户取消时记录 |

- **验收场景**（Gherkin）：
  - Given 患者已登录，进入预约挂号页，选择了科室"眼科"
    When 患者选择日期"2026-08-10"、时段"上午"，点击"确认预约"
    Then 系统生成预约单，状态为"待就诊"，展示预约成功页
    And 系统发送预约成功通知给患者
    And 该时段号源减少 1

  - Given 患者已登录，选择了某个时段
    When 该时段号源已满
    Then 系统提示"该时段已满，请选择其他时间"，预约按钮置灰不可点击

- **业务规则**：
  - 同一患者同一天同一时段只能预约 1 个号
  - 预约成功后 30 分钟内未支付自动取消（如涉及付费）
  - 患者可在就诊前 2 小时取消预约，超时不可取消

#### FR-1.2 查看检查报告

- **优先级**：P0

- **需求描述**：患者应能够在移动端查看已完成检查的报告结果。

- **业务流程**：
  1. 患者进入"我的报告"页面
  2. 系统展示所有已完成检查的报告列表（按时间倒序）
  3. 患者点击单条报告 → 进入报告详情页
  4. 系统展示报告全文（图文混排）

- **交互说明**：
  - **页面入口**：首页底部 Tab「我的」→ 点击「我的报告」入口
  - **操作路径**：「我的」→「我的报告」→ 报告列表页 → 点击目标报告 → 报告详情页
  - **页面布局与元素**：
    - **报告列表页**：顶部标题"我的报告"；Tab 切换（全部 / 已出 / 未出）；列表项（报告名称、检查日期、报告状态标签（已出为绿色"已出"、未出为灰色"未出"）、右侧箭头 > 表示可点击）
    - **报告详情页**：顶部标题"报告详情"，左侧返回按钮；报告基本信息区（患者姓名、检查项目、检查日期、报告医生、出报告时间）；报告正文区（支持图文混排，图片可点击放大查看）；底部无操作按钮，仅展示
  - **交互反馈**：
    - 点击列表项 → 跳转至报告详情页，加载时展示加载动画
    - 状态为"未出"的报告点击后 → 弹窗提示"报告尚未生成，请耐心等待"，不可进入详情
    - 图片点击 → 进入图片预览模式，支持双指缩放
    - 下拉刷新 → 列表重新加载，展示刷新动效
  - **状态变化**：
    - 报告状态为"未出"时，列表项灰色展示，" > " 箭头隐藏，不可点击
    - 报告状态从"未出"变为"已出"（系统后台更新）→ 患者再次进入列表时，状态自动刷新
  - **手势支持**：
    - 列表支持上下滑动
    - 图片预览支持双指放大缩小
    - 左滑返回上一页

- **字段详情**：

| 字段名称 | 字段标识 | 类型 | 必填 | 说明 |
|----------|----------|------|------|------|
| 报告 ID | report_id | String(32) | 是 | 主键 |
| 患者 ID | patient_id | String(32) | 是 | 关联患者表 |
| 检查项目 | exam_name | String(50) | 是 | 如"胸部CT平扫" |
| 检查日期 | exam_date | DateTime | 是 | - |
| 报告状态 | status | Enum | 是 | 已出/未出 |
| 报告内容 | content | Text | 否 | 图文混排内容 |
| 报告医生 | doctor_name | String(20) | 否 | - |
| 出报告时间 | issued_at | DateTime | 否 | - |

- **验收场景**（Gherkin）：
  - Given 患者已登录，且有一份已出的报告
    When 患者进入"我的报告"列表
    Then 列表中展示该报告，状态显示"已出"
    When 患者点击该报告
    Then 进入详情页，展示完整报告内容

  - Given 患者已登录，且有一份未出的报告
    When 患者进入"我的报告"列表
    Then 列表中展示该报告，状态显示"未出"，列表项不可点击
    When 患者点击该报告
    Then 弹窗提示"报告尚未生成，请耐心等待"

- **业务规则**：
  - 只有状态为"已出"的报告可查看详情
  - 报告内容支持图文混排，图片最多 20 张
  - 报告保留 3 年

### 6.2 医护端功能

> **模块描述**：面向医生和护士提供的诊疗相关操作功能。

#### FR-2.1 处理线上问诊

- **优先级**：P0

- **需求描述**：医生应能够在工作台上查看待处理的线上问诊申请，并进行接诊、开方等操作。

- **业务流程**：
  1. 医生登录工作台，查看待接诊列表
  2. 医生点击"接诊" → 进入问诊会话页面
  3. 医生与患者在线沟通（图文/语音）
  4. 医生根据诊断结果开具处方
  5. 患者在线支付处方费用
  6. 医生确认处方已支付，结束问诊

- **交互说明**：
  - **页面入口**：医护工作台首页 → 左侧导航「待接诊」卡片，数字角标显示待接诊数量
  - **操作路径**：
    工作台首页 → 点击「待接诊」→ 待接诊列表页 → 点击「接诊」→ 问诊会话页 → 输入消息沟通 → 点击「开方」→ 处方编辑页 → 填写处方信息 → 提交 → 返回会话页 → 确认患者已支付 → 点击「结束问诊」
  - **页面布局与元素**：
    - **工作台首页**：顶部医生信息（头像、姓名、科室）；数据概览卡片（今日接诊量、待接诊量、待处理处方量）；待接诊列表（展示最近 5 条，点击"查看全部"进入完整列表）；快捷操作区（「开始接诊」大按钮）
    - **待接诊列表页**：顶部标题"待接诊"；列表项（患者姓名、年龄、主诉摘要、申请时间、「接诊」按钮）；底部无操作按钮
    - **问诊会话页**：顶部患者信息栏（患者姓名、年龄、就诊卡号、状态标签"接诊中"）；中间聊天记录区（左侧为患者消息，右侧为医生消息，消息支持文字、图片、快捷卡片（如"建议来院就诊"））；底部输入区（文本输入框 + 表情按钮 + 图片上传按钮 + 语音按钮 + 快捷回复按钮）
    - **处方编辑页**：顶部标题"开具处方"；表单（诊断结果、用药列表（药品名称、规格、用法用量、天数）、医嘱说明）；底部「提交处方」按钮
  - **交互反馈**：
    - 点击「接诊」→ 问诊状态更新为"接诊中"，跳转至会话页，患者端同步显示"医生已接诊"
    - 发送消息 → 消息立即展示在聊天区，状态为"发送中" → 发送成功后状态变为"已读"（如患者已读）或"已送达"（如患者未读）
    - 收到新消息 → 页面标题栏闪烁 + 浏览器通知（如浏览器已授权）+ 消息列表滚动至最新
    - 提交处方 → 展示加载态"提交中..."，成功后面向患者展示待支付状态，医生端展示"待患者支付"标签
    - 患者支付成功 → 医生端实时收到通知，标签变为"已支付"，「结束问诊」按钮变为可点击
    - 点击「结束问诊」→ 弹窗二次确认"确定要结束本次问诊吗？" → 确认后问诊结束，返回工作台首页
    - 30 分钟无互动 → 系统自动结束问诊，工作台首页展示"已自动结束"通知
  - **状态变化**：
    - 问诊状态流转：待接诊 → 接诊中（医生点击接诊）→ 已开方（医生提交处方）→ 已支付（患者支付成功）→ 已结束（医生点击结束）
    - 工作台首页待接诊数字角标实时更新
  - **键盘/手势支持**：
    - 输入框支持 Enter 键发送消息
    - 聊天记录区下拉加载历史消息
    - 图片消息点击放大预览

- **字段详情**：

| 字段名称 | 字段标识 | 类型 | 必填 | 说明 |
|----------|----------|------|------|------|
| 问诊 ID | consult_id | String(32) | 是 | 主键 |
| 医生 ID | doctor_id | String(32) | 是 | - |
| 患者 ID | patient_id | String(32) | 是 | - |
| 状态 | status | Enum | 是 | 待接诊/接诊中/已开方/已结束/已取消 |
| 问诊类型 | type | Enum | 是 | 图文/语音/视频 |
| 主诉 | complaint | String(200) | 否 | - |
| 接诊时间 | accepted_at | DateTime | 否 | - |
| 结束时间 | ended_at | DateTime | 否 | - |

- **验收场景**（Gherkin）：
  - Given 医生已登录工作台，且有 1 条待接诊问诊
    When 医生点击"接诊"
    Then 问诊状态更新为"接诊中"，进入会话页面
    And 患者端同步显示"医生已接诊"

- **业务规则**：
  - 医生单次只能接诊 1 位患者（一对一问诊）
  - 接诊后 30 分钟内无互动，自动结束问诊

### 6.3 管理后台功能

> **模块描述**：面向医院管理员的系统配置和运营管理功能。

#### FR-3.1 科室配置

- **优先级**：P0

- **需求描述**：管理员应能够新增、编辑、删除科室信息，包括科室名称、简介、图标、排班规则等。

- **业务流程**：
  1. 管理员登录后台，进入「科室管理」页面
  2. 系统展示所有科室列表（含状态、医生数量）
  3. 管理员点击"新增科室" → 填写科室信息 → 提交
  4. 系统校验通过后保存，科室状态默认为"启用"
  5. 管理员可对已有科室进行编辑或"停用"操作

- **交互说明**：
  - **页面入口**：管理后台左侧导航 → 系统管理 →「科室管理」
  - **操作路径**：
    登录后台 → 左侧导航点击「科室管理」→ 科室列表页 → 点击「新增科室」→ 弹出新增弹窗 → 填写信息 → 点击「确认」→ 列表刷新
  - **页面布局与元素**：
    - **科室列表页**：顶部标题"科室管理" + 右上角「新增科室」按钮（主色调）；搜索框（支持名称搜索）；表格（列：科室名称、科室简介、状态（启用/停用标签）、医生数量、排序权重、操作（编辑/停用/删除按钮））；分页器
    - **新增/编辑弹窗**：弹窗标题"新增科室"/"编辑科室"；表单（科室名称（文本输入框，必填）、科室简介（多行文本框，选填）、排序权重（数字输入框，默认 0）、状态（开关，启用/停用））；底部「确认」「取消」按钮
  - **交互反馈**：
    - 点击「新增科室」→ 弹出弹窗，背景蒙层，弹窗居中
    - 填写科室名称 → 实时校验是否已存在同名科室 → 存在则下方红字提示"科室名称已存在"，「确认」按钮置灰
    - 点击「确认」→ 提交成功则 Toast 提示"新增成功"，弹窗关闭，列表刷新；提交失败则 Toast 提示错误原因
    - 点击「停用」→ 弹窗二次确认"确定要停用该科室吗？停用后患者端将不展示" → 确认后状态变为"停用"
    - 点击「删除」→ 弹窗二次确认"确定要删除该科室吗？删除前请确认该科室下无排班记录" → 如有排班则提示"该科室下有排班记录，无法删除"
  - **状态变化**：
    - 科室状态从"启用"→"停用"：患者端科室列表不再展示该科室，但患者历史预约记录中保留科室名称
    - 科室状态从"停用"→"启用"：患者端科室列表恢复展示

- **字段详情**：

| 字段名称 | 字段标识 | 类型 | 必填 | 说明 |
|----------|----------|------|------|------|
| 科室 ID | dept_id | String(32) | 是 | 主键 |
| 科室名称 | dept_name | String(30) | 是 | 唯一，如"眼科" |
| 科室简介 | description | String(200) | 否 | - |
| 状态 | status | Enum | 是 | 启用/停用 |
| 排序权重 | sort_order | Integer | 是 | 数字越小展示越靠前 |

- **验收场景**（Gherkin）：
  - Given 管理员已登录后台，进入科室管理页
    When 点击"新增科室"，填写名称"眼科"，简介"眼科疾病诊疗"，提交
    Then 系统保存成功，科室列表新增"眼科"，状态默认为"启用"

- **业务规则**：
  - 科室名称不可重复
  - 停用的科室不在患者端展示，但历史数据保留
  - 科室删除需先确认该科室下无排班记录

### 6.4 系统端功能

> **模块描述**：定时任务、消息推送、数据同步等系统级功能。

#### FR-4.1 预约到期提醒推送

- **优先级**：P1

- **需求描述**：系统应在患者预约就诊时间前 2 小时自动推送提醒通知。

- **业务流程**：
  1. 系统定时任务每小时扫描一次预约记录
  2. 筛选出距离就诊时间还有 2 小时的预约
  3. 调用消息推送能力发送通知
  4. 推送成功后记录日志

- **交互说明**：
  - **触发方式**：系统后台定时任务，每小时整点触发（如 08:00、09:00、10:00...）
  - **推送内容**：提醒通知，包含就诊人姓名、就诊科室、就诊时间、就诊地点
  - **推送目标**：患者绑定的消息接收账号
  - **无前端交互**，纯系统后台行为

- **字段详情**：

| 字段名称 | 字段标识 | 类型 | 必填 | 说明 |
|----------|----------|------|------|------|
| 预约 ID | appointment_id | String(32) | 是 | 关联预约表 |
| 患者 OpenID | open_id | String(64) | 是 | 微信 OpenID |
| 推送时间 | push_time | DateTime | 是 | 实际推送时间 |
| 推送状态 | status | Enum | 是 | 成功/失败 |
| 失败原因 | fail_reason | String(200) | 否 | 推送失败时的错误信息 |

- **验收场景**（Gherkin）：
  - Given 系统中有 1 条预约记录，就诊时间为 2026-08-10 10:00
    When 当前时间为 2026-08-10 08:00（扫描触发）
    Then 系统向该患者发送提醒通知
    And 推送日志记录成功

- **业务规则**：
  - 同一条预约只推送 1 次
  - 推送失败时重试 3 次，间隔 5 分钟
  - 已取消/已完成的预约不触发推送
