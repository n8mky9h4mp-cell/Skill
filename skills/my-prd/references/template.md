# PRD 模板与撰稿细则（my-prd）

建议路径：`docs/prd-{项目名称}.md`。详尽交互示例见 [examples.md](examples.md)。

## 必含 8 章

1. 文档信息  
2. 版本历史（强制；「待补充」记为「需后续确认」）  
3. 项目背景与业务场景  
4. 产品概述（定位 / 服务对象 / 架构）  
5. 用户角色  
6. 功能需求（**按角色分模块**）  
7. 非功能需求  
8. 附录（可选：术语表、参考文档、设计稿、会议记录）

## 截图处理

- 已上传图片 → `![描述](图片链接)`
- **未上传 → 不插图片占位**，用文字写清交互

## 第 6 章：交互说明六要素（强制）

每个子功能必须写清，**禁止**「详见设计稿」：

1. 页面入口  
2. 操作路径  
3. 页面布局与元素  
4. 交互反馈  
5. 状态变化  
6. 键盘/手势支持（如适用）

## 需求编号（按角色）

| 前缀 | 角色/端 |
|------|---------|
| FR-1.x | 患者端（或等价端） |
| FR-2.x | 医护端 |
| FR-3.x | 管理后台 |
| FR-4.x | 系统端 |
| FR-5.x | 数据研发（如适用） |

多角色功能不得混在同一小节。

## 输出禁止

- 禁止输出自检清单 / 8.4 / 勾选完备性列表  
- 禁止无图时插入 `📷 待补充` 空占位
