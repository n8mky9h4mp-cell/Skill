# Cocos Creator 2D 项目架构

## 先检查再创建

现有项目先定位真实的 Cocos 项目根目录，再读取其中的 `package.json`、`settings/`、`assets/`、场景、脚本和版本控制状态；标准新项目的根目录是 `client/`。匹配现有命名与目录，不重排无关文件。没有项目时才创建最小 Cocos Creator 3.8+ TypeScript 结构。

## 目录与依赖边界

完整仓库结构、资源目录、命名和版本控制规则以 [project-structure.md](project-structure.md) 为准。本文件只补充运行架构：

- `core/` 不依赖具体题材、UI 或平台实现。
- `game/` 组合纯逻辑与 Cocos 组件，通过接口调用 `services/` 和 `platform/`。
- `ui/` 订阅游戏状态并发送用户意图，不复制胜负、奖励或数值计算。
- `platform/` 隔离 `wx`、`tt` 和编辑器模拟；平台回调先归一化，再通知业务层。
- `config/` 只提供类型化静态数据，不反向依赖场景节点和运行时服务。
- `bundles/`、远程资源和后端目录属于条件能力，只有 PRD 批准后才进入依赖图。

## 场景与生命周期

最小闭环通常为：

```text
启动 → 主界面 → 游戏 → 结算 → 再来一局
```

- 启动阶段只加载首屏必要内容和全局服务。
- 核心玩法使用清晰状态，例如准备、进行、暂停、成功、失败、结算。
- 前后台切换由平台适配层归一化后通知游戏，不在多个组件重复监听。
- 场景切换时注销监听、定时器和平台回调，避免重复奖励和内存增长。

## 逻辑与组件

- 数值、胜负、奖励、存档迁移等尽量写成与节点无关的 TypeScript 逻辑。
- Cocos `Component` 负责节点引用、输入和渲染协调，不承载所有业务规则。
- 只有实际复用时才抽象基类或管理器。
- 使用 `@property` 暴露编辑器需要配置的引用，启动时校验关键引用。
- 不为单个对象创建全局单例；全局服务数量保持最少。

## 资源

- 首包只保留启动与首局必要资源。
- 图集、纹理压缩、远程资源、缓存和 Asset Bundle 根据当前平台规则与实际体积决定。
- 不把易变化的包体数字写死在代码或文档模板中；构建时查询平台当前限制。
- 资源命名稳定，替换生成图片时不破坏引用。

## 预览策略

Web Mobile 用于快速验证公共玩法和 UI。平台登录、分享、广告、存储差异和生命周期必须在微信、抖音开发者工具或真机验证。
