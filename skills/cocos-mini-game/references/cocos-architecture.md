# Cocos Creator 2D 项目架构

## 先检查再创建

现有项目先读取 `package.json`、`settings/`、`assets/`、场景、脚本和版本控制状态。匹配现有命名与目录，不重排无关文件。没有项目时才创建最小 Cocos Creator 3.8+ TypeScript 结构。

## 推荐职责边界

```text
assets/
├── scenes/                 # 启动、主界面、游戏、结算等场景
├── scripts/
│   ├── core/               # 纯逻辑、状态机、数值和通用事件
│   ├── game/               # 当前玩法组件与规则
│   ├── ui/                 # 界面组件和交互
│   ├── platform/           # 统一接口、环境选择和平台实现
│   ├── services/           # 存档、配置、资源等项目服务
│   └── config/             # 类型化配置与常量
├── prefabs/                # 可复用节点与 UI 预制体
├── textures/               # 图片、图集和字体资源
├── audio/                  # 用户生成后接入的音效和 BGM
└── bundles/                # 仅在 PRD 需要时使用 Asset Bundle
```

这只是新项目起点。PRD 必须给出项目实际目录树，未使用的目录不要创建。

## 场景与生命周期

最小闭环通常为：

```text
启动 → 主界面 → 游戏 → 结算 → 再来一局
```

- 启动阶段只加载首屏必要内容和全局服务。
- 核心玩法使用清晰状态，例如准备、进行、暂停、成功、失败、结算。
- 前后台切换由平台适配层归一化后通知游戏，不在多个组件重复监听。
- 场景切换时注销监听、定时器和平台回调，避免重复奖励和内存增长。

## 逻辑与组件

- 数值、胜负、奖励、存档迁移等尽量写成与节点无关的 TypeScript 逻辑。
- Cocos `Component` 负责节点引用、输入和渲染协调，不承载所有业务规则。
- 只有实际复用时才抽象基类或管理器。
- 使用 `@property` 暴露编辑器需要配置的引用，启动时校验关键引用。
- 不为单个对象创建全局单例；全局服务数量保持最少。

## 资源

- 首包只保留启动与首局必要资源。
- 图集、纹理压缩、远程资源、缓存和 Asset Bundle 根据当前平台规则与实际体积决定。
- 不把易变化的包体数字写死在代码或文档模板中；构建时查询平台当前限制。
- 资源命名稳定，替换生成图片时不破坏引用。

## 预览策略

Web Mobile 用于快速验证公共玩法和 UI。平台登录、分享、广告、存储差异和生命周期必须在微信、抖音开发者工具或真机验证。
