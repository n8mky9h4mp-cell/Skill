# 项目准备度与合规

## 先识别产品类型

如果用户说“微信小程序游戏”，先判断：

- 需要实时游戏循环、Canvas/WebGL、游戏广告、Cocos 构建产物：按微信小游戏处理。
- 主要是表单、内容页、工具页或轻交互：可能是普通微信小程序，应先确认而不是套用本 Skill。

## 准备度清单

在 PRD 中记录状态、负责人和阻塞：

| 类别 | 检查项 |
| --- | --- |
| 引擎 | Cocos Creator 精确版本、项目能否打开、TypeScript 编译状态 |
| 微信 | 主体、小游戏账号、App ID、开发者工具、体验成员 |
| 抖音 | 主体、小游戏应用、App ID、开发者工具、测试权限 |
| 网络 | 合法域名、HTTPS、对象存储/CDN（如使用） |
| 合规 | 当前备案/审批要求、隐私说明、适龄与未成年人要求、客服渠道 |
| 版权 | 图片、字体、角色、代码及后续音频的来源和授权证明 |
| 商业化 | 广告位申请状态、测试广告规则、平台运营规范 |

## 时效性规则

平台政策、资质、备案、审批、适龄、隐私和广告规则会变化。执行项目时：

1. 优先查询微信、抖音、监管部门或发行渠道的当前官方页面。
2. 记录查询日期、来源链接和适用主体。
3. 将明确要求、尚不确定项和专业咨询项分开。
4. 不把历史对话、旧教程或二手文章当作最终法律结论。
5. 无法确定时建议用户向平台、发行方或合规专业人员确认。

## 安全边界

- AppSecret、支付密钥、服务端签名密钥和长期令牌不得写入客户端或版本库。
- 不自动操作线上账号、提交审核或发布版本。
- 不绕过域名校验、隐私授权、实名或平台审核。
- 开发者工具中的临时调试开关不能作为生产配置交付。

## 输出

把清单写入 `docs/game/PRD.md` 的“项目准备与合规”章节，并把用户操作项拆入 `docs/game/tasks.md`。缺失项不阻止无关开发，但必须在 `progress.md` 标记影响范围。
