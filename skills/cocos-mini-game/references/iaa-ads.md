# IAA 广告设计与实现

## 原则

- 广告是可选增强，不是核心游戏能否继续的单点依赖。
- 激励与玩家主动选择绑定，奖励和观看成本清晰。
- 插屏放在自然停顿点；横幅避开安全区域和核心操作。
- 广告 API、测试广告和频控规则执行时查询对应平台当前文档。

## 激励视频状态机

```text
idle → loading → ready → showing → completed/cancelled/failed → idle
```

实现要求：

- 同一广告位同一时间只允许一次展示请求。
- 只有平台明确报告完整播放时才返回 `completed: true`。
- 关闭、失败、超时、状态不明或能力不可用都不发奖励。
- 使用一次性奖励令牌或局内标记防止重复回调、重复点击和场景重入造成重复发放。
- 展示结束后按平台生命周期决定预加载下一条广告。
- 失败时给出轻量提示并允许玩家继续游戏或稍后重试。

## 插屏与横幅

- 插屏候选点：结算结束、章节切换、返回主界面等自然停顿。
- 设置会话内冷却和最小间隔，避免连续弹出。
- 横幅加载失败不改变布局；显示前计算安全区域，关闭后释放或复用对象。
- 不把关闭按钮、奖励按钮或普通 UI 设计成误触广告。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 完整播放 | 仅发放一次奖励 |
| 中途关闭 | 不发奖励，可继续游戏 |
| 加载失败 | 不阻断游戏，提示可重试 |
| 重复点击 | 只存在一个展示请求 |
| 重复回调 | 奖励幂等 |
| 切后台/恢复 | 状态可恢复或明确失败，不悬挂 |
| 平台不支持 | 返回 `unsupported`，隐藏或降级入口 |

平台测试结果必须来自对应开发者工具或真机，编辑器模拟只验证业务分支。
