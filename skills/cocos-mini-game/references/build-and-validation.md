# 构建与验证

## 验证顺序

1. TypeScript 与项目静态检查。
2. Cocos 编辑器打开、资源导入和场景引用。
3. Web Mobile 核心玩法预览。
4. 微信小游戏构建与开发者工具。
5. 抖音小游戏构建与开发者工具。
6. 两端真机能力与性能。

前一步失败不代表后续全部停止；记录依赖关系并继续处理无关任务。

## 公共检查

- 启动、主界面、游戏、结算和再次开始闭环。
- 胜负、奖励、暂停、恢复和存档迁移。
- 不同屏幕比例、安全区域、触摸范围和文字可读性。
- 弱网、断网、超时、资源失败和重试。
- 启动时间、帧率、内存、Draw Call、纹理体积、场景切换和长时间运行。
- 前后台切换后定时器、音频、广告和游戏状态正确。

## 构建检查

- 使用项目精确 Cocos 版本对应的官方构建文档。
- 检查目标方向、启动场景、App ID、调试/发布配置和输出目录。
- 按当前平台规则检查主包、分包、远程资源和缓存，不引用旧限制。
- 构建产物中的 `game.json`、`project.config.json` 等配置与目标一致。
- 不直接手改生成目录中的长期逻辑；需要稳定修改时使用项目配置或受控构建模板。

## 状态记录

每项只能标记：

- `通过`：实际执行并满足条件。
- `失败`：实际执行但未满足，附错误。
- `未执行`：尚未运行。
- `受阻`：缺少工具、账号、权限、App ID、网络或真机，附恢复条件。

编辑器模拟不能替代平台开发者工具，开发者工具不能完全替代真机。最终报告分别列出 Web、微信和抖音状态。
