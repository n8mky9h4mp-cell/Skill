# 后端与数据决策

## 默认选择

首版默认纯客户端，使用平台本地存储完成设置和本地进度。不要因为“正式游戏通常有后端”就自动创建服务器、数据库或运营后台。

## 需要再次确认的触发条件

出现以下需求时，先在 PRD 说明范围、成本和安全影响，再征得用户确认：

- 跨设备或云端存档。
- 多人、实时交互或服务端权威玩法。
- 账号体系、跨平台身份合并。
- 服务端权威奖励、远程配置、活动或灰度开关。
- 排行榜、支付、订单或运营后台。
- 需要可信数据的广告奖励校验与风控。

## 服务端基本原则

引入后端后，不信任客户端提交的分数、奖励、货币和完成状态。至少评估：

- 会话和平台登录凭证校验。
- 参数边界、关卡状态和时长合理性。
- 幂等键、防重复领取和重复回调。
- 频率限制、异常日志和必要的人工复核。
- 配置版本、存档版本和向后兼容。
- 服务器时间而非客户端时间。

秘密只存在于服务端安全配置，不写入客户端、日志或版本库。

## 技术选型

根据已有团队技术栈、部署环境和需求选择后端，不固定 Flask、FastAPI、Node.js 或某种数据库。PRD 必须说明：

- 为什么需要后端。
- 数据所有权和一致性要求。
- 接口、存储、缓存和部署选择。
- 首版不做的能力。
- 本地与线上验证条件。
