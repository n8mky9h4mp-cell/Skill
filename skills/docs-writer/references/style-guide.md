# 风格指南（style-guide）

文档校对清单。按本文件逐项过，可消除大部分可读性问题。原则见 [SKILL.md 五原则](../SKILL.md)。

## 语态与人称

| 场景 | 用 | 例 |
| --- | --- | --- |
| 直接称呼读者 | **你** / you | "运行 `filesort .` 查看结果" |
| 共同动作 | **我们** / we | "我们先安装依赖" |
| 客观陈述 | 主动 + 现在时 | "该函数返回字符串" |
| 观点性引导 | 可用 **我** / I | 谨慎使用，仅限主观建议 |

**避免**：被动语态连串。"文件被扫描后被排序" → "扫描文件并排序"。

## 格式约定

| 元素 | 格式 | 例 |
| --- | --- | --- |
| 命令、变量、文件名 | `行内代码` | `pip install`、`config.yaml` |
| UI 元素、按钮、菜单项 | **加粗** | **运行** 按钮、**Settings** |
| 占位符 | 大写 | `API_KEY`、`USERNAME` |
| 强调 | *斜体*（克制） | 关键术语首次出现 |
| 代码块 | 带语言标签 | ` ```bash `、` ```python ` |

## 代码示例规范

每个示例必须满足：

1. **可运行**：完整、含必要 import 与上下文，读者复制即可跑。
2. **有输出**：紧接 `# Output:` 或独立代码块展示预期结果。
3. **有注释**：仅注释非显然逻辑；显而易见的代码不加注释。
4. **最新**：与当前版本一致；版本号、参数名、API 签名不要过时。

```python
def greet(name: str) -> str:
    """简短说明。"""
    return f"Hello, {name}"

# 示例用法
print(greet("world"))
# Output: Hello, world
```

## 术语处理

- **首次出现定义**：技术术语第一次提到时用一句话解释或括注。
- **一致性**：同一概念全文用同一个词，避免"函数/方法/过程"混用。
- **缩写**：首次 `完整词（ABBR）`，后续直接 `ABBR`。

## 常见反模式（校对清单）

写作与审校时逐条排查：

- [ ] **开头堆功能**：未先说价值主张，直接列特性
- [ ] **有描述无示例**：关键概念只有文字，没有可运行代码
- [ ] **被动语态连串**：连续多句"被…"结构
- [ ] **死板套模板**：机械照搬结构，不顾读者实际需要
- [ ] **超长句子**：单句超过 25 词
- [ ] **未定义术语**：堆砌专业词无解释
- [ ] **过时代码**：示例与当前版本不匹配
- [ ] **缺错误处理**：只讲成功路径，不讲常见失败
- [ ] **层级混乱**：H2 直接连 H4，或同级标题层级不一致
- [ ] **链接失效**：内部锚点、外部 URL、相对路径未验证

## 句长与密度

- 单句 ≤ 25 词（中文 ≤ 40 字）
- 一段一个主旨
- 列表项 ≤ 2 行，超长则拆子项或转表格
