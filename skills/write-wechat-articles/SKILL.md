# 微信公众号文章写作

写短而有用的文章。先核验，再提炼，只保留支撑核心结论的内容。

## 开始前

1. 读取 [references/article-patterns.md](references/article-patterns.md)，选择最小文章结构。
2. 读取 [references/wechat-formatting.md](references/wechat-formatting.md)，确定交付与图片格式。
3. 新写或补充事实性内容时，读取 [references/research-policy.md](references/research-policy.md)。
4. 完稿后读取 [references/quality-checklist.md](references/quality-checklist.md)，执行最多两轮压缩与核验。

## 默认受众与口吻

- 技术文章面向具备基础知识的开发者。
- AI 创作文章面向已经使用过相关工具的创作者。
- 使用一线实践者口吻，专业、直接、有判断。
- 不讲行业常识、注册流程和基础按钮，除非它们会影响结果。
- 不写成产品宣传稿，不虚构经历、测试或数据。

## 工作流程

1. 识别用户目标、现有材料、文章类型和核心读者收益。
2. 只有缺失信息会改变技术结论时，提出一个简短问题；其他情况直接继续。
3. 按研究规则检索官方文档、模型说明、源码、标准、论文或原始发布内容。
4. 提炼一个核心结论。选题过大时，收窄到一个能完整讲清的问题。
5. 选择最小文章结构，删除不需要的章节。
6. 优先写结论、关键代码或完整提示词、实际结果、限制和取舍。
7. 核验事实、版本、模型、平台、参数、代码行为和引用。
8. 删除重复解释、空泛过渡、常识性展开和总结式复述。
9. 判断图片是否真正帮助解释、证明或比较内容，只为必要图片设置占位。
10. 按规定格式交付，并用质量清单检查。最多修订两轮。

## 提示词处理

- 默认提供一个可直接复制的完整提示词。
- 用 `[角色设定]`、`[镜头运动]`、`[音乐风格]` 等明确占位符标记可替换变量。
- 标明适用工具、模型和用途；存在版本差异时简短说明。
- 只解释影响结果的关键变量，不逐句拆解或复述提示词。
- 未实际测试时，明确写“依据资料整理”或“建议尝试”。
- 不把单次生成结果描述为稳定能力。

## 图片处理

- 默认不自动生成图片，不声称已经上传到微信公众号素材库。
- 用户提供图片时，优先使用现有素材，并建议插入位置、裁剪比例和图片说明。
- 技术截图、效果对比和生成结果必须使用真实素材。
- AI 生成图片只用于封面或装饰插图，不代替事实证据。
- 使用网络图片时，标明来源并提示授权与转载风险。
- 没有必要配图时，不输出图片占位或配图清单。

正文统一使用可见占位：

```text
【配图 01｜用途｜建议比例｜替换为公众号素材库图片】
```

保持 Markdown 原稿、公众号排版稿和配图清单的编号与位置一致。

## 默认交付

按顺序输出：

1. 3 个标题候选
2. 60-100 字公众号摘要
3. Markdown 原稿
4. 内容一致的公众号排版稿
5. 配图清单，仅在正文需要图片时输出
6. 1 条封面图提示词
7. 1 句与正文直接相关的文末互动语

不要输出写作过程、长篇资料综述或逐条写作解释。用户指定交付范围时，以用户要求为准。

## 无法确认时

- 来源冲突时，优先采用最新一手资料，并简短指出差异。
- 无法确认版本、行为或授权时，明确标记，不猜测补齐。
- 无法运行示例时，只说明静态检查结果，不宣称已经验证。
- 两轮后仍缺少关键资料时，列出缺口并停止扩写。
