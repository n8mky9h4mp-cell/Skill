# AI 小说创作

创作可独立阅读、可持续连载，并便于后续改编为 AI 漫剧的中文小说。小说质量优先，改编信息与正文分开保存。

## 默认约定

- 使用简体中文。
- 中短篇优先，同时支持长篇连载。
- 一章对应一集漫剧。
- 每章默认 1500–2500 字，对应约 2–4 分钟漫剧。
- 所有作品保存在当前项目根目录的 `小说/`；用户指定其他位置时，以用户要求为准。
- 正文只放小说内容，制作资料单独保存在 `漫剧改编/`。

## 判断任务

先判断用户属于哪种任务：

1. **新建作品**：只有创意、题材、人物或梗概，需要从策划开始。
2. **续写作品**：已有作品目录，需要继续下一章或指定章节。
3. **修改作品**：需要重写、扩写或调整已有章节。

如果用户要把现成小说改成分镜、画面提示词或视频提示词，不在本技能中重复完成下游工作，改用仓库中的对应技能。

## 选择创作策略

根据主要受众和核心快感选择一种主策略：

- 男频为主：读取 [references/male-oriented.md](references/male-oriented.md)。
- 女频为主：读取 [references/female-oriented.md](references/female-oriented.md)。
- 创新短故事为主：读取 [references/innovative-short-story.md](references/innovative-short-story.md)。
- 混合题材：选一种主策略，必要时再读取一个补充策略，避免把多套规则平均混用。

凡是准备生成正文或漫剧改编资料，都读取
[references/manju-adaptation.md](references/manju-adaptation.md)。

## 新建作品

### 1. 提取已知信息

优先从用户原话提取：

- 核心创意和题材
- 男频、女频或创新短故事倾向
- 主角及其目标
- 核心冲突
- 时代与世界背景
- 叙事视角
- 预计篇幅或集数
- 目标受众和整体基调
- 用户明确要求保留或禁止的内容

### 2. 只确认关键缺口

仅当缺失信息会显著改变故事方向时才提问，例如主角身份、核心目标、感情线取向或结局类型。一次只问一个关键问题。

书名、普通配角姓名、次要场景等由你合理补全。用户说“直接写”“你来决定”时，不再追问。

### 3. 创建作品目录

使用可读的中文作品名创建：

```text
小说/
└── 作品名/
    ├── 00_作品设定.md
    ├── 01_角色设定.md
    ├── 02_故事总纲.md
    ├── 03_分集大纲.md
    ├── 04_创作进度.md
    ├── 正文/
    └── 漫剧改编/
```

目录名移除 `/`、`\`、`:` 等不适合路径的字符，不使用难以辨认的随机编号。

### 4. 先策划再写作

依次生成：

1. `00_作品设定.md`：题材、受众、核心卖点、主题、世界观、叙事方式和整体基调。
2. `01_角色设定.md`：身份、外貌、服装、性格、欲望、缺陷、关系、能力边界和视觉锚点。
3. `02_故事总纲.md`：主线、阶段目标、冲突升级、关键反转、高潮和结局方向。
4. `03_分集大纲.md`：一章对应一集，记录开场钩子、主要事件、情绪爆点和结尾钩子。
5. `04_创作进度.md`：当前阶段、已完成章节、人物状态、已埋伏笔、待回收线索。

通常先请用户确认设定和大纲，再开始正文。用户明确要求直接产出时，可以连续完成，但仍需把上述策划文件落盘。

### 5. 写章节

每章围绕一个明确变化展开：

```text
快速进入事件
→ 人物采取行动
→ 阻力或关系发生变化
→ 冲突升级
→ 产生情绪爆点或有效信息增量
→ 用选择、危机、悬念或合理反转收尾
```

这是一项节奏检查，不是固定公式。不要为了“爽点”牺牲因果，也不要强迫每章出现大反转。

正文保存为：

```text
正文/第001章_章节标题.md
```

正文文件只包含：

```markdown
# 第001章 章节标题

小说正文
```

随后创建：

```text
漫剧改编/第001集_改编资料.md
```

具体结构遵循 `references/manju-adaptation.md`。

### 6. 更新状态

写完每章后更新 `04_创作进度.md`：

- 已完成章节及一句话摘要
- 人物位置、关系、目标和能力状态
- 本章新增或推进的伏笔
- 已回收线索
- 下一章必须承接的事实

## 续写作品

续写前按顺序读取：

1. `00_作品设定.md`
2. `01_角色设定.md`
3. `02_故事总纲.md`
4. `03_分集大纲.md`
5. `04_创作进度.md`
6. 最近两章正文；信息不足时再向前读取
7. 与待写章节直接相关的漫剧改编资料

先列出本章必须承接的事实，再写正文。完成后创建对应改编资料并更新创作进度。

如果文件之间存在矛盾，停止继续扩大矛盾，指出冲突位置并给出最小改动方案。

## 修改作品

- 先确认要修改的章节和目标。
- 只修改指定章节及直接受影响的设定、分集大纲、改编资料和创作进度。
- 修改会影响后续章节时，先列出影响范围。
- 保留用户没有要求改变的文字、人物事实和文件结构。
- 不以“优化”为由重写无关章节。

## 写作质量要求

- 开篇尽快建立人物、异常、欲望或冲突，不用背景资料压住故事。
- 每场戏都至少完成一项功能：推进情节、改变关系、揭示人物或埋设线索。
- 对话体现立场差异，不写所有人物都能说的通用台词。
- 心理描写保持适量，优先用动作、表情、停顿、选择和环境互动呈现。
- 保持人物姓名、称谓、外貌、服装、能力、伤势、关系和时间线一致。
- 钩子来自因果链和人物选择，不凭空增加事故。
- 避免同义反复、空泛形容、过度总结和明显模板句。
- 不模仿在世作者的独特文风；改为使用用户需要的高层特征，如“冷峻克制”“快节奏群像”。

## 文件安全

- 写入前检查目标文件是否存在。
- 同名章节已存在时，不直接覆盖；询问用户是修改、另存还是取消。
- 用户明确要求修改已有章节时，可以原位更新。
- 写入失败时说明真实原因，不声称文件已保存。
- 不移动、删除或格式化与当前作品无关的文件。

## 完成前检查

### 结构

- [ ] 所有文件位于 `小说/作品名/`
- [ ] 五个基础资料文件齐全
- [ ] 一章对应一集
- [ ] 正文与改编资料分开
- [ ] 章节编号和集数连续

### 内容

- [ ] 本章目标、冲突、变化和结尾钩子清晰
- [ ] 人物和时间线与前文一致
- [ ] 没有用制作说明污染小说正文
- [ ] 场景、人物和关键道具适合后续可视化
- [ ] `04_创作进度.md` 已同步更新

完成后简洁汇报新增或修改的文件，并提供可点击路径。
